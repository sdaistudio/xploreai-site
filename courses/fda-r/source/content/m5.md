## 5.1 | Volatility: why the variance itself needs a model

Modules 2–4 modelled the **mean**: the expected return. Finance cares just as much about **risk**, because asset pricing is all about risk-adjusted return. The classical regression in Module 3 assumed **homoskedasticity**, a constant error variance. Market returns break that assumption every day.

> [concept] **Volatility clustering:** large moves tend to follow large moves, and calm days follow calm days. Think of March 2020, or oil during a Middle East flare-up. Clustering is the **precondition** for an ARCH effect. If you can see it in a returns chart, the variance is predictable and worth modelling.

### ARCH (Engle, 1982)

ARCH stands for autoregressive conditional heteroskedasticity. Today's variance depends on yesterday's **squared shocks**:

**ARCH(q): σₜ² = α₀ + α₁εₜ₋₁² + … + α_qεₜ₋_q²**

If the α's are significantly above zero, there's an ARCH effect. The drawback is that capturing long memory needs many lags, which eats degrees of freedom and can produce negative coefficients that make no sense for a variance.

### GARCH (Bollerslev, 1986)

GARCH adds **yesterday's variance** itself, so one term captures that long memory:

**GARCH(1,1): σₜ² = ω + α₁εₜ₋₁² + β₁σₜ₋₁²**

| Term | Name | Meaning |
|---|---|---|
| ω | Constant | The long-run baseline of variance |
| α₁ | ARCH term | Reaction to **news**: how much yesterday's surprise moves today's risk |
| β₁ | GARCH term | **Persistence**: how much yesterday's risk carries into today |
| α₁ + β₁ | | Close to 1 means shocks fade slowly. It must stay below 1 |

The procedure has three steps:

1. Fit a **mean model** (ARMA) to the returns.
2. Test its residuals for an **ARCH effect**.
3. If one is present, fit a **GARCH** model and forecast volatility.

### Step 1: a mean model

```r
AR_fit <- arima(returns, order = c(1, 0, 0))
AR_fit
residuals_AR <- residuals(AR_fit)
```

### Step 2: the ARCH LM test

H₀: there is **no ARCH effect**. We need to **reject** it before a GARCH model is justified.

```r
library(FinTS)
ArchTest(residuals_AR, lags = 12)
```

> [read] The p-value is essentially zero, so reject H₀. NIFTY's squared residuals are strongly autocorrelated, which means **today's risk depends on recent risk**. GARCH is justified.

### Step 3: fit GARCH(1,1)

`rugarch` separates the **specification** (what model) from the **fit** (estimate it on data).

```r
library(rugarch)
garch11_spec <- ugarchspec(
  variance.model     = list(model = "sGARCH", garchOrder = c(1, 1)),
  mean.model         = list(armaOrder = c(1, 0), include.mean = TRUE),
  distribution.model = "norm")
garch11_fit <- ugarchfit(spec = garch11_spec, data = returns)
round(garch11_fit@fit$matcoef, 6)
```

> [read] **mu** and **ar1** belong to the mean equation. **omega** is the variance constant. **alpha1** (about 0.1) is significant, so news moves volatility. **beta1** (about 0.87) is significant, so volatility is persistent. Their sum is about 0.98, close to 1: a shock takes weeks, not days, to wash out of NIFTY's volatility.

```r
sum(coef(garch11_fit)[c("alpha1", "beta1")])      # persistence
```

### Conditional volatility through time

```r h=4.2
cond_vol <- sigma(garch11_fit) * sqrt(252) * 100         # annualised, in %
plot(cond_vol, col = rust, main = "NIFTY 50: GARCH(1,1) annualised volatility (%)",
     grid.col = "#EDE4D3", yaxis.right = FALSE)
```

### Forecast volatility 90 days ahead

```r
garch_fc <- ugarchforecast(garch11_fit, n.ahead = 90)
sigma_fc <- as.numeric(sigma(garch_fc))
round(head(sigma_fc), 5)                         # daily sigma for T+1, T+2, ...
sqrt(sum(sigma_fc^2))                            # aggregate 90-day volatility
```

> [read] Variances add up over time, standard deviations don't. So you sum the 90 daily **variances** and then take the square root. The last line gives the expected spread of NIFTY's **total** return over the next 90 trading days. Here it's about 0.08: a one-standard-deviation band of roughly ±8% over the next three months.

```r h=4
plot(sigma_fc * 100, type = "l", lwd = 2.5, col = rust, xlab = "Days ahead", ylab = "Daily sigma (%)",
     main = "GARCH forecast: volatility drifts back to its long-run level")
abline(h = sqrt(coef(garch11_fit)["omega"] / (1 - sum(coef(garch11_fit)[c("alpha1", "beta1")]))) * 100,
       col = espresso, lty = 2)
```

> [try] Swap in `armaOrder = c(1, 1)` for the mean equation and re-run. The aggregate 90-day volatility barely changes. The mean model matters far less than the variance model when you're forecasting risk.

## 5.3 | Value at Risk and backtesting in R

**Value at Risk** answers one question: *how much could we lose on a bad day?* A 1-day 95% VaR of −1.3% means that on 95% of days the loss won't exceed 1.3%. On the other 5%, it will.

The data is the daily log return of an equal-weighted portfolio of Reliance, TCS, HDFC Bank, Infosys and ICICI Bank, 2023–2025.

```r
data <- read.csv(paste0(url, "portfolio_returns.csv"))
str(data)
data$Date <- as.Date(data$Date, format = "%d-%m-%Y")
returns <- data$Portfolio_Return
mu <- mean(returns); sigma <- sd(returns)
cat("Mean:", round(mu, 6), "  SD:", round(sigma, 6), "  Days:", length(returns), "\n")
conf_level <- 0.95; alpha <- 1 - conf_level
```

### Three ways to calculate VaR

| Method | How | Assumption |
|---|---|---|
| Historical | The 5th percentile of actual past returns | The past repeats; no distribution assumed |
| Parametric | μ + σ × z₀.₀₅, where z₀.₀₅ = −1.645 | Returns are normal |
| Monte Carlo | Simulate 10,000 returns, take the 5th percentile | The simulated model is right |

```r
hist_var  <- quantile(returns, probs = alpha)
param_var <- mu + sigma * qnorm(alpha)
set.seed(123)
sim_returns <- rnorm(10000, mean = mu, sd = sigma)
mc_var <- quantile(sim_returns, probs = alpha)

var_results <- data.frame(Method  = c("Historical", "Parametric", "Monte Carlo"),
                          VaR     = round(c(hist_var, param_var, mc_var), 5),
                          LossPct = round(-100 * c(hist_var, param_var, mc_var), 3))
var_results
```

### Backtesting: did reality break the VaR as often as it should?

A **violation** is a day when the actual return falls below the VaR. At 95%, you expect violations on 5% of days.

```r
n_obs <- length(returns)
backtest <- data.frame(Method   = var_results$Method,
                       Expected = n_obs * alpha,
                       Actual   = c(sum(returns < hist_var), sum(returns < param_var), sum(returns < mc_var)))
backtest$ViolationRatio <- round(backtest$Actual / backtest$Expected, 3)
backtest
```

> [read] A **ratio near 1** means the model is accurate. **Above 1** means more violations than promised, so the model **underestimates** risk. **Below 1** means it **overestimates** risk and is overly cautious. Historical VaR hits its expected count exactly, by construction, because it *is* the 5th percentile of this same sample. The parametric and Monte Carlo VaRs are breached only about 26–27 times against 37 expected (ratio ≈ 0.7), so the normal distribution makes them slightly too cautious here.

### The Kupiec test: is the gap statistically significant?

The Kupiec proportion-of-failures (POF) test asks whether the actual violation rate differs significantly from 5%. H₀: the model is correctly calibrated.

```r
kupiec <- function(x, n, p) {
  phat <- x / n
  lr <- -2 * (log((1 - p)^(n - x) * p^x) - log((1 - phat)^(n - x) * phat^x))
  c(LR = round(lr, 3), p.value = round(1 - pchisq(lr, df = 1), 3))
}
t(sapply(backtest$Actual, kupiec, n = n_obs, p = alpha))
```

> [read] Every p-value is above 0.05, so we **can't reject** correct calibration for any method. The parametric VaR is borderline, though (p ≈ 0.05). This is an **in-sample** check, because VaR was estimated and tested on the same days. A proper backtest re-estimates VaR each day using only past data. That's a rolling window, and it's the natural next step.

## 5.4 | The VaR framework: what it is, and what it misses

> [concept] **VaR = the maximum expected loss over a given holding period at a given confidence level.** For example, "With 95% confidence, our Rs 1,000 crore book won't lose more than Rs 50 crore over one week."

### The four ingredients

| Ingredient | Example |
|---|---|
| Portfolio value | Rs 1,000 crore |
| Confidence level | 95% or 99% |
| Holding period | 1 day, 10 days, 1 week |
| Volatility | From history, from σ, or from GARCH (Session 5.2) |

> [tip] Scale a 1-day VaR to h days with **VaR × √h**. This square-root-of-time rule assumes returns are independent from day to day. GARCH tells you they aren't quite, so use it as an approximation.

### Where VaR is used

- **Banks**: capital adequacy under Basel market-risk rules.
- **Treasury desks**: daily risk monitoring and trading limits.
- **Portfolio managers**: risk budgeting and capital allocation.
- **Regulators**: standardised, comparable risk reporting.

### Choosing a method

| | Historical | Parametric | Monte Carlo |
|---|---|---|---|
| Speed | Fast | Fastest | Slowest |
| Fat tails | Captured, if they're in the sample | Missed (assumes normal) | Only if you simulate them |
| Best for | Simple portfolios with long histories | Quick daily estimates | Options and other complex books |

### Limitations

- **It says nothing beyond the cutoff.** VaR tells you the threshold, not how bad the worst 5% of days get. **Expected Shortfall** (the average loss beyond VaR) fills that gap, and the Basel FRTB rules now use it.
- **It's backward-looking.** It's calm-period VaR that fails in a crisis.
- **It's sensitive to assumptions**: the window length, the distribution and the confidence level.

```r
ES_hist <- mean(returns[returns < hist_var])
c(VaR_95 = round(unname(hist_var) * 100, 2), ExpectedShortfall_95 = round(ES_hist * 100, 2))
```

> [read] VaR says the loss is worse than **1.33%** on 1 day in 20. Expected Shortfall says that on those days the **average** loss is about **1.84%**, roughly 40% worse. That gap is the tail risk VaR hides.
