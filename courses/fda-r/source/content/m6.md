## 6.1 | Event study: the COVID-19 lockdown and NIFTY 50

An **event study** measures how a specific piece of news moved a price, whether the news was a war, a policy announcement, an earnings surprise or a pandemic. The idea is to compare what actually happened with what would have happened **without** the event.

### The timeline

| Window | Purpose | Here |
|---|---|---|
| **Estimation window** | Estimate "normal" returns | 120 trading days before the event window |
| **Event day (t = 0)** | The first trading day under the news | 25 March 2020, the first session of India's national lockdown |
| **Event window** | Measure the reaction | t = −10 to t = +10 (21 trading days) |

### The formulas

- **Expected return** under the **constant-mean model**: E[R] is the average return over the estimation window. The market model (E[Rᵢ] = α + βRₘ) or Fama–French are the research-grade alternatives.
- **Abnormal return**: ARₜ = Rₜ − E[R]
- **Cumulative abnormal return**: CAR = Σ ARₜ
- **t-statistics**: t = AR₀ / σ_est for the event day, and t = CAR / (σ_est × √L) for a window of L days. If |t| > 1.96, the effect is significant at 5%.

```r
library(xts)
url <- "https://xploreai.co.in/courses/fda-r/data/"
rust <- "#E2571B"; espresso <- "#4A4238"
nifty <- read.csv(paste0(url, "NIFTY50.csv"))
nifty$Date <- as.Date(nifty$Date)
nifty <- subset(nifty, Date >= as.Date("2019-09-01") & Date <= as.Date("2020-05-31"))

returns_df <- data.frame(Date = nifty$Date[-1], Return = diff(log(nifty$Close)))
event_date <- as.Date("2020-03-25")
event_index <- which(returns_df$Date == event_date)
est_window <- 120; event_window <- 10

est_data <- returns_df[(event_index - event_window - est_window):(event_index - event_window - 1), ]
evt_data <- returns_df[(event_index - event_window):(event_index + event_window), ]
range(est_data$Date); range(evt_data$Date)
```

### Abnormal and cumulative abnormal returns

```r
exp_ret <- mean(est_data$Return)
sd_est  <- sd(est_data$Return)

evt_data$EventTime <- -event_window:event_window
evt_data$AR  <- evt_data$Return - exp_ret
evt_data$CAR <- cumsum(evt_data$AR)
evt_data$t_AR <- evt_data$AR / sd_est
print(transform(evt_data, Return = round(Return * 100, 2), AR = round(AR * 100, 2),
                CAR = round(CAR * 100, 2), t_AR = round(t_AR, 2)), row.names = FALSE)
```

```r
CAR_full <- sum(evt_data$AR)
t_CAR <- CAR_full / (sd_est * sqrt(nrow(evt_data)))
cat("Event-day AR:", round(evt_data$AR[evt_data$EventTime == 0] * 100, 2), "%  t =",
    round(evt_data$t_AR[evt_data$EventTime == 0], 2), "\n")
cat("CAR(-10,+10):", round(CAR_full * 100, 2), "%  t =", round(t_CAR, 2), "\n")
```

> [read] Two numbers tell the story. On the **event day** NIFTY actually *rose*, with a large positive abnormal return. Markets had sold off for weeks, and the relief rally came as the lockdown and early stimulus took shape. Over the **full window**, though, the **CAR is deeply negative** and its |t| is well above 1.96, so the period around the lockdown destroyed significant value. Always read the event day and the window separately.

### Visualise

```r h=5.6
par(mfrow = c(2, 1), mar = c(3, 4.2, 2.6, 1))
barplot(evt_data$AR * 100, names.arg = evt_data$EventTime, col = ifelse(evt_data$AR < 0, rust, "#C9B8A3"),
        border = NA, ylab = "AR (%)", main = "Abnormal returns, t = -10 to +10")
abline(h = 0, col = espresso)
plot(evt_data$EventTime, evt_data$CAR * 100, type = "b", pch = 19, col = rust, lwd = 2,
     xlab = "", ylab = "CAR (%)", main = "Cumulative abnormal return")
abline(v = 0, h = 0, col = espresso, lty = 2)
par(mfrow = c(1, 1))
```


> [try] Narrow the window to [−3, +3] or [−1, +1] by changing `event_window`, then re-run. Shorter windows isolate the news itself. Longer windows capture how the market digested it.

## 6.2 | Does the US lead India? Causality between NIFTY and the S&P 500

This applies Module 4 end to end: stationarity, then lags, then Johansen, then a VAR or VECM, then Granger.

```r
sp <- read.csv(paste0(url, "SP500.csv"))
nf <- read.csv(paste0(url, "NIFTY50.csv"))
price_data <- na.omit(merge(data.frame(Date = nf$Date, nifty_close = nf$Close),
                            data.frame(Date = sp$Date, sp500_close = sp$Close), by = "Date"))
price_data$Date <- as.Date(price_data$Date)
dim(price_data)
```

```r h=4.4
par(mar = c(3, 4.5, 3, 4.5))
plot(price_data$Date, price_data$nifty_close, type = "l", col = rust, lwd = 1.6, xlab = "", ylab = "NIFTY 50",
     main = "NIFTY 50 (orange, left) and S&P 500 (dark, right)")
par(new = TRUE)
plot(price_data$Date, price_data$sp500_close, type = "l", col = espresso, lwd = 1.2, axes = FALSE, xlab = "", ylab = "")
axis(4); par(mar = c(5, 4, 4, 2) + .1)
```

### Step 1: orders of integration

```r
library(urca)
nifty_d <- diff(price_data$nifty_close); sp_d <- diff(price_data$sp500_close)
c(nifty_level = summary(ur.df(price_data$nifty_close))@teststat,
  nifty_diff  = summary(ur.df(nifty_d))@teststat,
  sp_level    = summary(ur.df(price_data$sp500_close))@teststat,
  sp_diff     = summary(ur.df(sp_d))@teststat)
```

> [read] Both levels are above −1.95 and both differences are far below it, so **both indices are I(1)**. Next stop: Johansen.

### Step 2: lags and cointegration

```r
library(vars)
VARselect(data.frame(nifty_d, sp_d), lag.max = 10, type = "const")$selection
jo <- ca.jo(data.frame(nifty = price_data$nifty_close, sp500 = price_data$sp500_close),
            type = "trace", ecdet = "const", K = 2)
cbind(test = round(jo@teststat, 2), jo@cval)
```

> [read] The **r = 0** statistic is **below** its 5% critical value, so we can't reject "no cointegration". NIFTY and the S&P 500 don't share a stable long-run path, so a VECM is the wrong tool. Use a **VAR on the differenced (stationary) series** instead. Note that `ca.jo()` needs `K ≥ 2` even if the selected lag is 1.

### Step 3: the VAR on daily changes

```r
diff_data <- data.frame(nifty = nifty_d, sp500 = sp_d)
var1 <- VAR(diff_data, lag.max = 5, ic = "AIC", type = "const")
round(coef(var1)$nifty[1:4, ], 4)        # NIFTY equation: does the S&P lead?
round(coef(var1)$sp500[1:4, ], 4)        # S&P equation: does NIFTY lead?
```

### Step 4: Granger causality in both directions

```r
library(lmtest)
k <- var1$p
grangertest(nifty ~ sp500, order = k, data = diff_data)
grangertest(sp500 ~ nifty, order = k, data = diff_data)
```

> [read] **S&P → NIFTY**: F ≈ 45 with a p-value of essentially zero, so the US Granger-causes India. **NIFTY → S&P**: p ≈ 0.06, which isn't significant at 5%. Causality is **unidirectional, from the US to India**. The VAR coefficients agree: `sp500.l1` in the NIFTY equation is large and highly significant.

> [warn] Part of this is the clock. The US market closes about 10 hours **after** India's on the same calendar date. So a row that pairs "today's" S&P close with "tomorrow's" NIFTY is really pairing **consecutive** sessions, and one lag of the S&P is effectively news that India hasn't traded yet. Here the lead–lag is real, but it isn't mysterious.

## 6.3 | The machine learning framework for finance

**Machine learning** means programming computers to optimise a criterion from data, so that they learn the patterns themselves instead of being given an equation. It sits at the **cognitive** end of the analytics ladder from Session 1.1.

Why it matters in finance now: data has exploded, storage is cheap, decisions need to be fast, and markets are **noisy and non-linear**, which linear models miss.

### Two families

| | Supervised | Unsupervised |
|---|---|---|
| Training data | Labelled (we know the answer) | Unlabelled |
| Continuous target | **Regression** (predict the return) | n/a |
| Categorical target | **Classification** (predict Up or Down) | n/a |
| Goal | Predict | **Cluster** similar observations |
| Finance example | Next-day direction, credit default | Grouping stocks by behaviour, fraud anomalies |

### The models in Session 6.4

| Model | How it works | Use it when… |
|---|---|---|
| Linear regression | A straight-line equation | You need an interpretable baseline |
| Decision tree | A sequence of if/then splits | You want readable trading rules or threshold effects |
| Random forest | Hundreds of trees, then a majority vote | The data is noisy and you need robustness |
| Support vector machine (SVM) | Finds the widest boundary between classes, curved by a kernel | Up and Down aren't separated by a straight line |
| Neural network | Layers of weighted nodes | There's lots of data and hidden interactions |

> [warn] **The traps that matter most in finance**
> **Overfitting**: a model that memorises the past and fails tomorrow.
> **Structural breaks**: relationships change, for example after COVID.
> **Look-ahead bias**: using information you wouldn't have had at the time.
> **Data snooping**: re-running until something "works". Choosing the right *design* matters more than choosing a fancy algorithm.

## 6.4 | Machine learning in R: predicting NIFTY's direction

**Target:** will NIFTY close **Up** or **Down** tomorrow? The regression version predicts the size of the return.

**Features**, all known at the close of day *t* and used to predict day *t+1*:

- the last three days' returns
- the S&P 500's return
- the 5-day and 20-day moving averages relative to price
- the 14-day RSI
- the 10-day volatility
- the change in volume

```r eval=false
install.packages(c("TTR", "caret", "rpart", "randomForest", "e1071", "neuralnet"))
```

```r
library(TTR)
nf <- read.csv(paste0(url, "NIFTY50.csv")); sp <- read.csv(paste0(url, "SP500.csv"))
d <- na.omit(merge(data.frame(Date = nf$Date, close = nf$Close, volume = nf$Volume),
                   data.frame(Date = sp$Date, sp_close = sp$Close), by = "Date"))
d <- subset(d, Date >= "2018-01-01" & volume > 0)

d$ret     <- c(NA, diff(log(d$close))) * 100
d$sp_ret  <- c(NA, diff(log(d$sp_close))) * 100
d$lag1    <- d$ret; d$lag2 <- c(NA, head(d$ret, -1)); d$lag3 <- c(NA, NA, head(d$ret, -2))
d$ma5_gap  <- (d$close / SMA(d$close, 5) - 1) * 100
d$ma20_gap <- (d$close / SMA(d$close, 20) - 1) * 100
d$rsi14    <- RSI(d$close, 14)
d$vol10    <- runSD(d$ret, 10)
d$vol_chg  <- c(NA, diff(log(d$volume)))

# the target is TOMORROW's return: every feature is known today
d$next_ret  <- c(d$ret[-1], NA)
d$Direction <- factor(ifelse(d$next_ret > 0, "Up", "Down"))
ml_df <- na.omit(d)
nrow(ml_df); table(ml_df$Direction)
```

### Split by time, not at random

```r
predictors <- c("lag1", "lag2", "lag3", "sp_ret", "ma5_gap", "ma20_gap", "rsi14", "vol10", "vol_chg")
cut   <- floor(0.8 * nrow(ml_df))
train <- ml_df[1:cut, ];  test <- ml_df[(cut + 1):nrow(ml_df), ]
range(train$Date); range(test$Date)
fml_reg <- as.formula(paste("next_ret ~", paste(predictors, collapse = " + ")))
fml_cls <- as.formula(paste("Direction ~", paste(predictors, collapse = " + ")))
```

> [warn] The lecture uses a random 80/20 split (`sample()`) and same-day features. On time series both leak the future into training and **inflate accuracy**. Here we train on 2018 to early 2024 and test only on the later period the model has never seen. That's how you'd use the model in practice.

### 1. Linear regression (the baseline)

```r
library(caret)
lm_model <- lm(fml_reg, data = train)
round(summary(lm_model)$coefficients, 4)
lm_pred <- predict(lm_model, test)
c(adj_R2 = round(summary(lm_model)$adj.r.squared, 4),
  RMSE = round(RMSE(lm_pred, test$next_ret), 3), MAE = round(MAE(lm_pred, test$next_ret), 3),
  RMSE_naive = round(RMSE(rep(mean(train$next_ret), nrow(test)), test$next_ret), 3))
```

> [read] Only two features matter. The **S&P 500's return** is strongly positive: the US session closes after India's, so its move is genuine overnight news for NIFTY. **Yesterday's NIFTY return** is mildly negative, a small reversal effect. But the adjusted R² is only about 8%, and out of sample the RMSE (0.766) is no better than the naive forecast of "always predict the training average" (0.762). Predicting the *size* of tomorrow's return is very hard. In the lecture's version, with same-day features, the R² was about 25%, because today's S&P "explained" today's NIFTY.

### 2. Decision tree

```r h=5
library(rpart)
tree_model <- rpart(fml_cls, data = train, method = "class", control = rpart.control(cp = 0.004, maxdepth = 4))
tree_pred  <- predict(tree_model, test, type = "class")
par(xpd = NA, mar = c(1, 1, 2, 1))
plot(tree_model, uniform = TRUE, branch = .6, margin = .06, col = espresso, main = "Decision tree: Up or Down tomorrow?")
text(tree_model, use.n = TRUE, cex = .72, col = rust)
```

```r
confusionMatrix(tree_pred, test$Direction, positive = "Up")
```

> [read] The **confusion matrix** shows predicted classes in rows and actual classes in columns. **Accuracy** = correct predictions / total. Always compare it with the **No Information Rate**, the accuracy you'd get by always predicting the more common class. A model is only useful if it beats that, and the p-value `[Acc > NIR]` tells you whether it does so significantly.

### 3. Random forest

```r
library(randomForest)
set.seed(123)
rf_model <- randomForest(fml_cls, data = train, ntree = 500)
rf_pred  <- predict(rf_model, test)
confusionMatrix(rf_pred, test$Direction, positive = "Up")$overall[c("Accuracy", "AccuracyNull", "AccuracyPValue")]
```

```r h=4.4
varImpPlot(rf_model, main = "Random forest: which features matter?", pch = 19, col = rust)
```

### 4. Support vector machine

```r
library(e1071)
svm_model <- svm(fml_cls, data = train, kernel = "radial")
svm_pred  <- predict(svm_model, test)
confusionMatrix(svm_pred, test$Direction, positive = "Up")$overall[c("Accuracy", "AccuracyNull", "AccuracyPValue")]
```

### 5. Neural network

Neural nets need inputs on a common scale. Scale the test set with the **training** set's min and max, so no test information leaks back.

```r
library(neuralnet)
mins <- sapply(train[predictors], min); maxs <- sapply(train[predictors], max)
sc <- function(df) as.data.frame(scale(df[predictors], center = mins, scale = maxs - mins))
nn_train <- sc(train); nn_train$Up <- as.numeric(train$Direction == "Up")
set.seed(123)
nn_model <- neuralnet(as.formula(paste("Up ~", paste(predictors, collapse = " + "))),
                      data = nn_train, hidden = 3, linear.output = FALSE, stepmax = 1e6)
nn_prob <- compute(nn_model, sc(test))$net.result
nn_pred <- factor(ifelse(nn_prob > 0.5, "Up", "Down"), levels = c("Down", "Up"))
confusionMatrix(nn_pred, test$Direction, positive = "Up")$overall[c("Accuracy", "AccuracyNull", "AccuracyPValue")]
```

```r h=5.2
plot(nn_model, rep = "best", col.entry = espresso, col.hidden = rust, col.out = espresso,
     col.intercept = "#C9B8A3", show.weights = FALSE, information = FALSE, fontsize = 10)
```

### Compare all four

```r h=4.2
acc <- data.frame(Model = c("Decision tree", "Random forest", "SVM", "Neural net"),
                  Accuracy = 100 * c(mean(tree_pred == test$Direction), mean(rf_pred == test$Direction),
                                     mean(svm_pred == test$Direction), mean(nn_pred == test$Direction)))
nir <- 100 * max(prop.table(table(test$Direction)))
acc$Accuracy <- round(acc$Accuracy, 1); acc
bp <- barplot(acc$Accuracy, names.arg = acc$Model, col = rust, border = NA, ylim = c(0, 75),
              ylab = "Out-of-sample accuracy (%)", main = "Next-day direction: models vs 'always say Up'")
abline(h = nir, col = espresso, lty = 2, lwd = 2)
text(bp, acc$Accuracy + 3, paste0(acc$Accuracy, "%"), col = espresso, font = 2)
```

> [read] The dashed line is the **No Information Rate** (about 51%): the accuracy of always predicting the more common outcome. Honest out-of-sample models beat it by only **3–7 points**. The simple decision tree does best (58%, significantly above the NIR), and almost all of its edge comes from one feature, the overnight S&P move. The fancier models don't win. The lecture's 60–73% figures come from same-day features and a random split, so this gap is the most valuable lesson in the module.

> [warn] Even 58% direction accuracy isn't money in the bank. By the time NIFTY opens, the S&P's overnight move is already in the opening price, so a close-to-close prediction doesn't translate directly into a trade. Measure ML trading ideas on **returns after costs**, not on accuracy.

> [try] Recreate the lecture's setup to see the inflation for yourself. Use **same-day** `sp_ret` as a feature with today's direction as the target, then split with `sample()`. Accuracy jumps, because the S&P's same-day close already contains much of NIFTY's next-morning news.

> [concept] **Accuracy or interpretability?** A linear model or a single tree is easy to explain to a risk committee. A forest or a neural network may squeeze out a little more accuracy. In finance, a model nobody can explain rarely makes it to production.
