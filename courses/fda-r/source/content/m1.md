## 1.1 | What financial data analytics is

W. Edwards Deming said it best: *"In God we trust; all others must bring data."* Finance is a field where every decision (what to buy, how much to lend, how much capital to hold) is a bet on numbers. Analytics is the discipline of making those bets with evidence instead of instinct. The flip side is **GIGO: garbage in, garbage out**. The right tool on the wrong data still gives the wrong answer.

### The four levels of analytics

| Level | Question it answers | Finance example |
|---|---|---|
| Descriptive | What happened? | Average NIFTY return and volatility last year |
| Predictive | Why did it happen, and what happens next? | Does the rupee drive IT-stock returns? Next month's forecast |
| Prescriptive | What should we do? | Optimal hedge ratio, portfolio weights |
| Cognitive | Can a machine decide for us? | ML credit scoring, algorithmic trading |

Almost everything in finance comes back to two numbers: **return** (the mean) and **risk** (the volatility). This course builds tools for both. Modules 2–4 model the mean with regression, ARIMA and VAR. Module 5 models the volatility with GARCH and Value at Risk.

### Levels of measurement

The type of a variable decides which statistics are even legal to compute:

| Scale | Example | Order? | Meaningful zero? | Valid average |
|---|---|---|---|---|
| Nominal | Sector, gender | No | No | Mode only |
| Ordinal | Credit rating AAA > AA > A | Yes | No | Median, mode |
| Interval | Temperature in °C | Yes | No | Mean, median, mode |
| Ratio | Price, income, volume | Yes | Yes | Mean, median, mode |

Nominal and ordinal together are **categorical** data. Interval and ratio together are **continuous** data.

### Three shapes of data

- **Cross-sectional**: many units at one point in time, such as the P/E ratios of all NIFTY 50 firms on 31 March.
- **Time series**: one unit observed over time, such as daily NIFTY closes. Most finance data looks like this.
- **Panel**: many units over time, such as quarterly results of 50 firms over 10 years.

> [concept] This course starts with cross-sectional tools (regression in Module 3) and then spends most of its time on time series, because stock prices, exchange rates, GDP and commodity prices all arrive as a sequence over time. The two big goals are **establishing causality** and **forecasting**.

## 1.2 | R, RStudio and your first commands

**R** is a free, open-source statistical language created by Ross Ihaka and Robert Gentleman in 1993. **RStudio** is the workbench that sits on top of it. Install R first from CRAN (cran.r-project.org), then RStudio Desktop from posit.co. RStudio does nothing without R underneath.

Why R and not Excel, EViews or Stata? It's free, and new statistical methods usually appear as R packages first. Banks, the Big Four audit firms and regulators also use it daily.

Base R ships with built-in help. You'll use these constantly:

```r eval=false
license()      # what licence R is released under
demo()         # list of built-in demonstrations
help.start()   # opens the HTML manuals in your browser
help(sum)      # help page for one function
?mean          # shortcut for the same thing
```

The first thing to learn in any statistics package is to use it as a calculator:

```r
2 + 2
5 * 5
100 - 20
100 / 20
```

> [read] The `[1]` before each answer is R telling you "this is element 1 of the result". Every answer in R is a vector, even when it holds a single number.

## 1.3 | The RStudio interface: scripts, console and objects

RStudio has four panes:

| Pane | Where | What it's for |
|---|---|---|
| Source (script) | Top-left | Where you write and save code |
| Console | Bottom-left | Where code runs and output appears |
| Environment / History | Top-right | Every object you've created |
| Files / Plots / Packages / Help | Bottom-right | Charts, installed packages, documentation |

> [tip] Write code in a script (File → New File → R Script), not in the console. Run the current line with **Ctrl + Enter** (Cmd + Enter on Mac), or select everything with Ctrl + A and run it all. Save the script and you can rebuild your whole analysis tomorrow.

### Objects and assignment

You store a value in a named **object** with `<-` (or `=`). R is **case-sensitive**: `Y` and `y` are two different objects.

```r
x <- 100
Y <- 150
x + Y
200 + x
```

Use an object before you create it and R refuses:

```r
x + y
```

```r
y <- 300
x + y
(x + y) * y    # anything after # is a comment and is ignored
```

### Text needs quotes

```r
today <- "today we are learning the basics of RStudio"
now   <- 'it is a sunny day here'   # single quotes work too
today
now
```

> [warn] The error `object 'y' not found` is the most common message you'll see. It almost always means a typo, the wrong case, or a line you forgot to run. Read every error. R tells you exactly what it couldn't find.

## 1.4 | R programming basics: vectors, sequences and matrices

### Functions

A function takes inputs inside round brackets and returns a result.

```r
sum(2, 3, 5)
sqrt(25)
rep(1, times = 3)
```

### Vectors: the basic unit of data in R

`c()` (for *combine*) builds a vector. A vector can hold numbers or text, but not a mix of both.

```r
q <- c(1, 2, 5)
p <- c("India", "China", "USA", "Japan")
q
p
```

### Sequences

`1:10` counts in whole steps. For any other step size, use `seq(from, to, by)`.

```r
1:10
c(1, 100, 0.5)          # NOT a sequence, just three numbers
h <- seq(1, 100, 0.5)   # 1, 1.5, 2, ... 100
head(h, 12)
length(h)
```

### Picking elements with [ ]

```r
h[1]
h[10]
p[3]
```

### Matrices

A matrix is a grid with rows and columns. R fills it **column by column**.

```r
A <- matrix(0, nrow = 3, ncol = 4)
A
B <- matrix(1:12, nrow = 3, ncol = 4)
B
B[2, 3]      # row 2, column 3
```

> [tip] If you type an incomplete command, the console prompt changes from `>` to `+` because R is waiting for the rest. Finish the line or press **Esc**. **Ctrl + L** clears the console.

## 1.7 | Data cleaning II: fixing problems, returns and a first chart

### Standardise the text

`mutate()` changes or adds columns. `str_to_title()` capitalises the first letter of each word, like Excel's PROPER().

```r
df <- df %>%
  mutate(Company = str_to_title(Company),
         Sector  = str_to_title(Sector))
unique(df$Company)
unique(df$Sector)
```

### Remove duplicates, then fill gaps

`distinct()` keeps one copy of each row. For a price series, **forward fill** is a sensible fix: carry the last known price forward. Always sort by date first.

```r
df <- df %>%
  distinct() %>%
  mutate(Date = as.Date(Date, format = "%d-%m-%Y")) %>%
  arrange(Date) %>%
  fill(Closing_Price, Volume, .direction = "down")
nrow(df)
colSums(is.na(df))
```

> [concept] Other options for missing values are deleting the row (only if that won't bias the result), replacing with the mean or median, or interpolating between neighbours. Forward fill suits prices because the last traded price really is the best guess.

### Find the outlier with the IQR rule

A box plot draws the five-number summary. Anything beyond **1.5 × IQR** from the box is flagged as an outlier.

```r h=4
rust <- "#E2571B"; espresso <- "#4A4238"
boxplot(df$Closing_Price, horizontal = TRUE, col = "#FBE9DF", border = espresso,
        main = "ABC Limited closing price: one value is not like the others")
```

```r
Q1 <- quantile(df$Closing_Price, 0.25)
Q3 <- quantile(df$Closing_Price, 0.75)
IQR_value <- Q3 - Q1
lower_bound <- Q1 - 1.5 * IQR_value
upper_bound <- Q3 + 1.5 * IQR_value
c(lower = lower_bound, upper = upper_bound)
df %>% filter(Closing_Price < lower_bound | Closing_Price > upper_bound)
df <- df %>% filter(Closing_Price >= lower_bound, Closing_Price <= upper_bound)
summary(df$Closing_Price)
```

### Calculate returns

Prices aren't comparable across stocks, but returns are. There are two versions:

| Return | Formula | Why use it |
|---|---|---|
| Simple | Rₜ = Pₜ / Pₜ₋₁ − 1 | Easy to read: "+1.2% today" |
| Log | rₜ = ln(Pₜ / Pₜ₋₁) | Adds up over time; standard in models |

```r
df <- df %>%
  arrange(Date) %>%
  mutate(Simple_Return = Closing_Price / lag(Closing_Price) - 1,
         Log_Return    = log(Closing_Price / lag(Closing_Price)))
head(df[, c("Date", "Closing_Price", "Simple_Return", "Log_Return")])
```

> [read] The first return is `NA` because day 1 has no previous price. For small moves the simple and log returns are almost identical. They only drift apart on big days.

### Summarise and plot

```r
df %>% summarise(Mean_Price  = mean(Closing_Price),
                 SD_Price    = sd(Closing_Price),
                 Mean_Return = mean(Simple_Return, na.rm = TRUE),
                 SD_Return   = sd(Simple_Return, na.rm = TRUE),
                 Mean_Volume = mean(Volume))
```

```r h=4.4
ggplot(df, aes(Date, Closing_Price)) +
  geom_line(colour = rust, linewidth = 1) +
  geom_point(colour = rust, size = 1.8) +
  labs(title = "ABC Limited: clean closing price", x = NULL, y = "Price (Rs)") +
  theme_minimal(base_size = 12)
```

> [try] Re-run the chart *before* removing the outlier. The 999 spike squashes every other point into a flat line. That's why you clean before you chart.
