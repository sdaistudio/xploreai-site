## 3.1 | Introduction to predictive analytics

Predictive modelling starts with **regression**, a term that goes back to Francis Galton's "regression to the mean". The idea is to explain changes in one variable (Y) through changes in others (X). Both must actually vary: if either one is constant, there's nothing to explain.

| Role | Other names |
|---|---|
| Dependent variable (Y) | Explained, response, regressand, outcome, endogenous |
| Independent variable (X) | Explanatory, predictor, regressor, covariate, exogenous |
| Control variable | Included to hold other effects constant, not of direct interest |

### The linear model

**Y = α + βX + ε**

- **α (intercept)**: the value of Y when X = 0. For example, what a household spends with zero income.
- **β (slope)**: the change in Y for a one-unit change in X. If β = 0.8, each extra rupee of income adds 80 paise of spending. A negative β means the two move in opposite directions.
- **ε (error)**: actual minus predicted. No relationship is perfect, and ordinary least squares (OLS) picks the line that minimises the squared errors.

When the classical assumptions hold (Session 3.3), OLS is **BLUE**: the Best Linear Unbiased Estimator.

### Which model fits which data?

| Y (dependent) | X (independent) | Model |
|---|---|---|
| Continuous | Continuous | Simple or multiple linear regression |
| Continuous | Categorical | Dummy-variable regression |
| Categorical | Continuous | Logistic regression |
| Categorical | Categorical | Classification techniques |

## 3.2 | Simple and multiple regression in R

The data is cross-sectional: 24 employees, each with a monthly salary (in Rs '000s), a performance rating out of 10, years of experience and number of certifications.

```r
url <- "https://xploreai.co.in/courses/fda-r/data/"
salary <- read.csv(paste0(url, "salary.csv"))
str(salary)
```

### Simple regression: Salary on Experience

`lm()` fits a linear model. The `~` reads as "is regressed on".

```r
model3 <- lm(Salary ~ Experience, data = salary)
summary(model3)
```

> [read] Read every regression in **three steps**.
> **1. R²**: what share of the variation in salary does experience explain? Higher is better, but a very high R² on time-series data can be spurious.
> **2. F-test**: H₀ says every slope is zero. If its p-value is below 0.05, reject H₀: the model is useful overall.
> **3. Coefficients**: check each p-value (or the stars: *** means p < 0.001), then read the sign and size. Here every extra year of experience adds the `Experience` estimate to salary, measured in Rs '000.

### Using the equation to predict

```r
coef(model3)
coef(model3)[1] + coef(model3)[2] * 20          # by hand: someone with 20 years
predict(model3, newdata = data.frame(Experience = c(5, 10, 20)))
```

```r
rust <- "#E2571B"; espresso <- "#4A4238"
plot(salary$Experience, salary$Salary, pch = 19, col = rust, cex = 1.3,
     xlab = "Experience (years)", ylab = "Salary (Rs '000)", main = "Salary vs experience, with the OLS line")
abline(model3, col = espresso, lwd = 2.5)
```

### Multiple regression

Add rating and certifications to the model:

```r
model4 <- lm(Salary ~ Rating + Experience + Certifications, data = salary)
summary(model4)
```

> [read] With several regressors, use **Adjusted R²**. It penalises every extra variable, so you can't inflate it by adding noise (the principle of parsimony). Notice that the experience coefficient has **shrunk** compared with model 3. Some of what experience was "explaining" really belonged to rating and certifications.

> [try] Fit `lm(Salary ~ Rating, data = salary)` and `lm(Salary ~ Certifications, data = salary)` yourself and interpret them with the same three steps.

## 3.3 | The assumptions of the classical linear regression model

OLS is only BLUE if seven assumptions hold:

| # | Assumption | What breaks if it fails | How to check |
|---|---|---|---|
| 1 | Linear in **parameters** (X² or 1/X is fine, β² is not) | Wrong model form | Theory, residual plots |
| 2 | Correctly specified, with no relevant variable left out | Biased coefficients | Theory, RESET test |
| 3 | No (perfect) multicollinearity among the X's | Unstable, inflated standard errors | Correlations, **VIF** |
| 4 | Errors have zero mean: E(ε) = 0 | Biased intercept | `mean(resid())` |
| 5 | **Homoskedasticity**: constant error variance | Wrong standard errors and p-values | **Breusch–Pagan** |
| 6 | Errors are normally distributed | Unreliable t and F tests in small samples | Histogram, Shapiro–Wilk |
| 7 | **No autocorrelation** of errors | Over-confident p-values (time series) | **Durbin–Watson** |

> [concept] Cross-sectional data mostly runs into problems with assumptions **3 and 5**. Time-series data adds **7**: this month's error tends to look like last month's error, because of trends, seasons and cycles.

## 3.4 | Testing the assumptions: cross-sectional data

### Multicollinearity: correlations and VIF

```r h=5.5
library(psych)
pairs.panels(salary[, -1], hist.col = rust, col = espresso, stars = TRUE)
```

The **variance inflation factor** shows how much each coefficient's variance is inflated by its correlation with the other X's.

```r eval=false
install.packages(c("car", "lmtest"))
```

```r
library(car)
vif(model4)
```

> [read] The usual rule of thumb: **VIF > 10** is serious, so drop the variable. **5–10** calls for judgement. **Below 5** (stricter authors say below 3) is no problem. All three values here are close to 1, so the regressors are not collinear.

### Zero mean of errors

```r
error_model4 <- resid(model4)
mean(error_model4)       # effectively zero
```

### Homoskedasticity: the Breusch–Pagan test

Squared residuals stand in for the error variance. Plot them first, then test.

```r
plot(error_model4^2, pch = 19, col = rust, ylab = "Squared residual", xlab = "Employee",
     main = "Error variance proxy: no obvious funnel")
library(lmtest)
bptest(model4)
```

> [read] H₀: the errors are **homoskedastic**. If p > 0.05, fail to reject, and the assumption holds. If p < 0.05, the variance changes across observations, so transform Y (log or Box-Cox) or use robust standard errors.

## 3.5 | Testing the assumptions: time-series data

The data is 80 quarters (2006–2025) of one firm's financial ratios. The question is what drives firm value, measured by **Tobin's Q**.

```r
CF_data <- read.csv(paste0(url, "CF_data.csv"))
dim(CF_data)
model_CF <- lm(Firm_Value_TobinsQ ~ ROA + Leverage_Ratio + Debt_Equity_Ratio + Interest_Coverage +
                 Capital_Intensity + Current_Ratio + Policy_Interest_Rate + Sales_Growth, data = CF_data)
round(vif(model_CF), 2)
```

> [read] Leverage ratio and debt-to-equity are almost the same thing measured two ways, so their VIFs explode well past 10. Interest coverage, which is built from leverage, is inflated too. Drop the two leverage measures and refit.

```r
model_CF2 <- lm(Firm_Value_TobinsQ ~ ROA + Interest_Coverage + Capital_Intensity +
                  Current_Ratio + Policy_Interest_Rate + Sales_Growth, data = CF_data)
round(vif(model_CF2), 2)
summary(model_CF2)
```

> [read] Every VIF is now below 10. Interest coverage sits just above 5, in the judgement zone, and it's significant, so keep it. Sales growth, ROA and the current ratio drive firm value most clearly here.

### Error mean and heteroskedasticity

```r
mean(resid(model_CF2))
bptest(model_CF2)
```

### Box-Cox: what transformation would help?

Box-Cox searches for the power λ that makes the errors best behaved. Read off the λ at the peak: **0 means take the log, 0.5 the square root, 1 means no transformation, and −1 means 1/Y**.

```r
library(MASS)
bc <- boxcox(formula(model_CF2), data = CF_data, lambda = seq(-2, 3, 0.05))
bc$x[which.max(bc$y)]     # best lambda
```

> [read] The peak is at about 1.35, but the 95% interval (the dotted lines) runs from about 0.5 to 2.2 and **includes 1**. No transformation is needed, which agrees with the Breusch–Pagan result.

### Autocorrelation: the Durbin–Watson test

```r
durbinWatsonTest(model_CF2)
```

```r h=4.2
plot(resid(model_CF2), type = "b", pch = 19, cex = .6, col = rust,
     ylab = "Residual", xlab = "Quarter", main = "Residuals over time: runs of positives and negatives")
abline(h = 0, col = espresso, lty = 2)
```

> [read] **DW ≈ 2** means no autocorrelation. Well **below 2** means positive autocorrelation and well above 2 means negative. Here DW is clearly below 2 and its p-value is under 0.05, so the errors are autocorrelated. You can see it in the chart: the residuals come in streaks instead of bouncing randomly around zero.

> [warn] This is the core problem with running OLS on time series. The fix is to **test each series for stationarity first** (Module 2), transform or difference them, and only then estimate. Module 4 builds models designed for exactly this.
