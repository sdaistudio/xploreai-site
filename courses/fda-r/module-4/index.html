Session 4.1

Time-series components and ARIMA models

Every time-series project in this course follows the same opening routine:

1. Declare the data as a time series with ts(). 2. Plot it. 3. Test for stationarity with ADF. 4. Transform it if it's non-stationary (difference it, or take log differences). 5. Re-test the transformed series. 6. Only then forecast or test causality.

ARIMA(p, d, q): forecasting a series from its own past

A univariate model predicts a series using nothing but its own history, such as NIFTY's next 20 days or GDP's next 12 quarters.

PartMeaningEquation piece
AR(p)Autoregressive: today depends on the last p valuesφ₁yₜ₋₁ + … + φₚyₜ₋ₚ
I(d)Integrated: difference d times to make it stationaryΔᵈyₜ
MA(q)Moving average: today depends on the last q forecast errorsθ₁εₜ₋₁ + … + θ_qεₜ₋_q

Choosing p, d and q by hand means trying (1,1,0), (0,1,1), (2,1,1) and so on, then keeping the model with the lowest AIC. forecast::auto.arima() does that search for you.

Regression is not causality

Yₜ = α + βXₜ + εₜ links two things that happen at the same time. For X to cause Y, X has to come first:

Yₜ = α + Σ φᵢ Yₜ₋ᵢ + Σ βⱼ Xₜ₋ⱼ + εₜ

There are three rules: test both directions (X → Y and Y → X), test the short run and the long run, and always include Y's own lags, because a good causality model is autoregressive.

Choosing the causality framework

Stationarity of the seriesFrameworkSession
All stationary at level, I(0)Granger causality + VAR4.3–4.4
All I(1), stationary after one differenceJohansen cointegration + VECM4.5
A mix of I(0) and I(1)ARDL bounds test4.6

Session 4.3

Causality with VAR, part 1: stationarity, lags and Granger

Does the Bitcoin spot market lead the futures market, or the other way round? Start with returns.

R
bitcoin <- read.csv(paste0(url, "bitcoin.csv"))
spot_R_T   <- ts(bitcoin$Spot_Returns,   frequency = 252, start = c(2017, 245))
future_R_T <- ts(bitcoin$Future_Returns, frequency = 252, start = c(2017, 245))
Tip

The start and frequency arguments only label the x-axis. Being a few days off doesn't change anything statistical. For daily trading data, about 252 days a year is standard.

R
par(mfrow = c(2, 1), mar = c(2.5, 4, 2.5, 1))
plot(spot_R_T,   col = rust,     main = "Bitcoin spot returns",    ylab = "")
plot(future_R_T, col = espresso, main = "Bitcoin futures returns", ylab = "")
par(mfrow = c(1, 1))

Step 1: both must be stationary

R
summary(ur.df(spot_R_T))@teststat
summary(ur.df(future_R_T))@teststat
Console output

             tau1
statistic -31.395
How to read it

Both statistics are far below the 5% critical value of −1.95, so both return series are I(0). That makes this a job for Granger causality and VAR.

Step 2: choose the lag length

How to read it

AIC, HQ, SC (Schwarz/BIC) and FPE are four information criteria. When they disagree, this course goes with AIC. The lag always comes from the effect (dependent) variable.

Step 3: Granger causality in both directions

In grangertest(effect ~ cause, order = k) the effect goes on the left. H₀: the cause does not Granger-cause the effect.

R
library(lmtest)
lag_spot   <- VARselect(spot_R_T,   lag.max = 10)$selection[["AIC(n)"]]
lag_future <- VARselect(future_R_T, lag.max = 10)$selection[["AIC(n)"]]
grangertest(future_R_T ~ spot_R_T,   order = lag_future)   # does spot lead futures?
grangertest(spot_R_T   ~ future_R_T, order = lag_spot)     # does futures lead spot?

Causality with VAR, part 2: estimating and reading the VAR

A VAR fits one equation for each variable, each regressed on the lags of every variable. In VAR(data.frame(Y, X)) the first column is the one you treat as the effect.

R
model1 <- VAR(data.frame(future = future_R_T, spot = spot_R_T),
              type = "const", lag.max = 5, ic = "AIC")
model1$p                                         # lag chosen by AIC
round(coef(model1)$future, 4)                    # the futures equation only

A picture of causality: impulse responses

An impulse-response function (IRF) traces how one series reacts over the next few days to a one-standard-deviation shock in the other.

R
ir <- irf(model1, impulse = "spot", response = "future", n.ahead = 8, boot = TRUE, runs = 200)
plot(ir, main = "Futures returns after a shock to spot returns", col = rust)
How to read it

The x-axis counts days after the shock, starting at 1 for the shock day itself. Futures barely move on the shock day, then jump about 1.2 percentage points the next day, and the effect has died out within two to three days. The dashed lines are a 95% bootstrap band: wherever it excludes zero, the response is significant. This is spot leading futures by roughly one day.

Session 4.5

Causality with VECM: when prices share a long-run path

Prices, unlike returns, are usually I(1). If two I(1) prices are tied together in the long run, they are cointegrated: they can drift apart briefly, but an error-correction force pulls them back.

R
BS_T <- ts(bitcoin$Spot_Price,   frequency = 252, start = c(2017, 245))
BF_T <- ts(bitcoin$Future_Price, frequency = 252, start = c(2017, 245))
ts.plot(BS_T, BF_T, col = c(rust, espresso), lwd = c(2, 1), ylab = "USD",
        main = "Bitcoin spot (orange) and futures (dark) prices")

Step 1: both prices are I(1)

R
c(spot_level   = summary(ur.df(BS_T))@teststat,
  spot_diff    = summary(ur.df(diff(BS_T)))@teststat,
  future_level = summary(ur.df(BF_T))@teststat,
  future_diff  = summary(ur.df(diff(BF_T)))@teststat)
Console output

     0.44451    -32.64372      0.44243    -32.70949
How to read it

Both levels sit above −1.95, so they're non-stationary. Both first differences sit far below it, so they're stationary. Both prices are I(1), which points to Johansen and VECM.

Look at the row r = 0. If the test statistic is greater than the 5% critical value, reject "no cointegration": the prices share a long-run relationship. Then check r <= 1: if you can't reject it, there is exactly one cointegrating vector. Without cointegration a VECM makes no sense; you'd use a VAR on differences instead (Session 6.2).

How to read it

The spot equation's ect1 is positive. The long-run relation is normalised on futures (ECT = futures − 1.003 × spot), so when futures trade above spot, a positive loading pushes spot up towards futures. Both markets close the gap, but futures do most of the work (−0.60 vs +0.33). Price discovery happens mainly in spot, which is the same story the Granger test told.

Watch out

Some of this lead comes from timing. Yahoo's Bitcoin spot "close" is midnight UTC, while CME futures settle at 4 pm Chicago time, so the two closes aren't simultaneous. Always check whether a lead–lag result could just be a clock mismatch. It's the same issue you'll meet with NIFTY and the S&P 500 in Session 6.2.

Tip

The lecture uses tsDyn::VECM(data, lag = 5, r = 1, estim = "ML"), which gives the same model with a different printout. cajorls() ships with urca, so there's nothing extra to install.

Session 4.6

Causality with ARDL: when the orders of integration are mixed

What if one series is I(0) and the other I(1)? Spot returns are I(0) and futures prices are I(1). VAR needs everything I(0), and VECM needs everything I(1). ARDL (autoregressive distributed lag) works with the mix, and it has two more advantages:

  • Y and X can have different lag lengths.
  • The current value Xₜ can enter the model.

Yₜ = α + Σ φᵢ Yₜ₋ᵢ + β₀Xₜ + Σ βⱼ Xₜ₋ⱼ + εₜ

The long run: the Pesaran–Shin–Smith bounds test

Below the I(0) lower boundNo cointegration
Above the I(1) upper boundCointegration, so check the error-correction term
In betweenInconclusive

The idea

Module 4 in one line: all I(0) → Granger + VAR. All I(1) → Johansen + VECM. Mixed → ARDL. Whatever you pick, test both directions, separate the short run from the long run, and never confuse a series' own lags with causality.
