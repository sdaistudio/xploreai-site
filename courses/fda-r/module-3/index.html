Session 3.1

Introduction to predictive analytics

Predictive modelling starts with regression, a term that goes back to Francis Galton's "regression to the mean". The idea is to explain changes in one variable (Y) through changes in others (X). Both must actually vary: if either one is constant, there's nothing to explain.

RoleOther names
Dependent variable (Y)Explained, response, regressand, outcome, endogenous
Independent variable (X)Explanatory, predictor, regressor, covariate, exogenous
Control variableIncluded to hold other effects constant, not of direct interest

The linear model

Y = α + βX + ε

  • α (intercept): the value of Y when X = 0. For example, what a household spends with zero income.
  • β (slope): the change in Y for a one-unit change in X. If β = 0.8, each extra rupee of income adds 80 paise of spending. A negative β means the two move in opposite directions.
  • ε (error): actual minus predicted. No relationship is perfect, and ordinary least squares (OLS) picks the line that minimises the squared errors.

When the classical assumptions hold (Session 3.3), OLS is BLUE: the Best Linear Unbiased Estimator.

Which model fits which data?

Y (dependent)X (independent)Model
ContinuousContinuousSimple or multiple linear regression
ContinuousCategoricalDummy-variable regression
CategoricalContinuousLogistic regression
CategoricalCategoricalClassification techniques

How to read it

Read every regression in three steps.

1. R²: what share of the variation in salary does experience explain? Higher is better, but a very high R² on time-series data can be spurious.

2. F-test: H₀ says every slope is zero. If its p-value is below 0.05, reject H₀: the model is useful overall.

3. Coefficients: check each p-value (or the stars: * means p < 0.001), then read the sign and size. Here every extra year of experience adds the Experience estimate to salary, measured in Rs '000.

Session 3.3

The assumptions of the classical linear regression model

OLS is only BLUE if seven assumptions hold:

#AssumptionWhat breaks if it failsHow to check
1Linear in parameters (X² or 1/X is fine, β² is not)Wrong model formTheory, residual plots
2Correctly specified, with no relevant variable left outBiased coefficientsTheory, RESET test
3No (perfect) multicollinearity among the X'sUnstable, inflated standard errorsCorrelations, VIF
4Errors have zero mean: E(ε) = 0Biased interceptmean(resid())
5Homoskedasticity: constant error varianceWrong standard errors and p-valuesBreusch–Pagan
6Errors are normally distributedUnreliable t and F tests in small samplesHistogram, Shapiro–Wilk
7No autocorrelation of errorsOver-confident p-values (time series)Durbin–Watson
The idea

Cross-sectional data mostly runs into problems with assumptions 3 and 5. Time-series data adds 7: this month's error tends to look like last month's error, because of trends, seasons and cycles.

Session 3.4

Testing the assumptions: cross-sectional data

Multicollinearity: correlations and VIF

R
library(psych)
pairs.panels(salary[, -1], hist.col = rust, col = espresso, stars = TRUE)

The variance inflation factor shows how much each coefficient's variance is inflated by its correlation with the other X's.

Rshown, not run here
install.packages(c("car", "lmtest"))
R
library(car)
vif(model4)
Console output
        Rating     Experience Certifications 
        1.1501         1.2366         1.1550
How to read it

The usual rule of thumb: VIF > 10 is serious, so drop the variable. 5–10 calls for judgement. Below 5 (stricter authors say below 3) is no problem. All three values here are close to 1, so the regressors are not collinear.

Zero mean of errors

R
error_model4 <- resid(model4)
mean(error_model4)       # effectively zero
Console output
[1] 7.6328e-17

Homoskedasticity: the Breusch–Pagan test

Squared residuals stand in for the error variance. Plot them first, then test.

R
plot(error_model4^2, pch = 19, col = rust, ylab = "Squared residual", xlab = "Employee",
     main = "Error variance proxy: no obvious funnel")
library(lmtest)
bptest(model4)
Console output
	studentized Breusch-Pagan test

data:  model4
BP = 3.98, df = 3, p-value = 0.26
How to read it

H₀: the errors are homoskedastic. If p > 0.05, fail to reject, and the assumption holds. If p < 0.05, the variance changes across observations, so transform Y (log or Box-Cox) or use robust standard errors.

Box-Cox: what transformation would help?

Box-Cox searches for the power λ that makes the errors best behaved. Read off the λ at the peak: 0 means take the log, 0.5 the square root, 1 means no transformation, and −1 means 1/Y.

R
library(MASS)
bc <- boxcox(formula(model_CF2), data = CF_data, lambda = seq(-2, 3, 0.05))
bc$x[which.max(bc$y)]     # best lambda
Console output
[1] 1.35
How to read it

The peak is at about 1.35, but the 95% interval (the dotted lines) runs from about 0.5 to 2.2 and includes 1. No transformation is needed, which agrees with the Breusch–Pagan result.

Autocorrelation: the Durbin–Watson test

R
durbinWatsonTest(model_CF2)
Console output
 lag Autocorrelation D-W Statistic p-value
   1         0.27145        1.4548   0.004
 Alternative hypothesis: rho != 0
R
plot(resid(model_CF2), type = "b", pch = 19, cex = .6, col = rust,
     ylab = "Residual", xlab = "Quarter", main = "Residuals over time: runs of positives and negatives")
abline(h = 0, col = espresso, lty = 2)
How to read it

DW ≈ 2 means no autocorrelation. Well below 2 means positive autocorrelation and well above 2 means negative. Here DW is clearly below 2 and its p-value is under 0.05, so the errors are autocorrelated. You can see it in the chart: the residuals come in streaks instead of bouncing randomly around zero.

Watch out

This is the core problem with running OLS on time series. The fix is to test each series for stationarity first (Module 2), transform or difference them, and only then estimate. Module 4 builds models designed for exactly this.
